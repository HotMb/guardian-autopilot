# Guardian Studio — local AI image archive

**Status:** Windows desktop shell and browser Studio are implemented; release validation is incomplete. Human-confirmed file changes only, updated 14 October 2026.
**Design source:** [`DESIGN.md`](../DESIGN.md)
**Interaction contract:** [`UX-CONTRACT.md`](../UX-CONTRACT.md)

## Product job

Help creators understand where locally generated image storage is going, monitor one explicitly selected output folder, inspect supported generation metadata, and review exact duplicates plus heuristic visual-variant candidates before deciding manually what to keep. Storage triage is the primary job; CleanCode is a separate code-maintenance capability in the same repository. Willingness to pay and category demand remain {{UNVALIDATED}}.

## Current user flow

1. Start Guardian Studio from the Windows desktop app or CLI. The desktop app serves the packaged interface over the secure `guardian://studio` origin; the browser/CLI app is served only on `127.0.0.1`. Both begin with explicitly synthetic sample data. The CLI can optionally monitor one local image folder with `guardian studio --watch <image-folder>`; this watcher is not available in the packaged desktop app.
2. Choose a folder through the browser's read-only directory picker, with a compatibility file-input fallback. No write permission is requested.
3. See the supported image count and aggregate bytes, then review up to the 10,000 largest files. Guardian checks byte-identical duplicates and creates separate visual-pattern suggestions for supported raster files. Switch between the sortable list and a contact sheet; both use the same filters, search, 40-image page, and manual review selection. In Similar candidates, the contact sheet places candidates from each visual-hint group side by side while keeping each full path visible. Archives beyond the entry cap or retained review set are explicitly marked partial.
4. Select a PNG to inspect supported generation metadata. Prompt/workflow values remain in memory for the selected file and are revealed only after an explicit disclosure action.
5. Select exact files manually from any review view. Similarity suggestions are based on a small local perceptual hash and can include false matches; inspect previews and paths. A complete inventory/exact-duplicate scan is required before Guardian enables archiving.
6. Review the exact paths and sizes shown inline, then choose **Archive selection**. After the browser grants write access to the selected folder, Guardian creates a marked `Corbeille` folder inside it. Guardian copies each selected image there, verifies the bytes, records the operation, and removes the source only after verification. A failed or cancelled copy leaves the source in place.
7. The separate Corbeille section lists archived paths and sizes. Restore only into the selected source folder after checking the original relative path is absent; the verified Corbeille copy remains until the user reviews its inline path list, checks the acknowledgement, and activates **Delete permanently**. This irreversible action deletes only verified Guardian copies. A failed restore may leave a partial target file, which must be inspected before retrying.

## Supported scope

- Local-only HTML/CSS/JavaScript app inside a Windows Electron shell or supported browser; no hosted scan, account, analytics, telemetry, cloud sync, or file-upload route. The desktop uses an allowlisted `guardian://studio` protocol; browser/CLI mode exposes one same-origin read-only status endpoint for the optional local watcher.
- Browser scanning uses `showDirectoryPicker({mode: 'read'})` where available; the compatibility file-input picker remains read-only. Archive is offered only where directory handles support separately granted `readwrite` permission. Each permission request follows a direct user gesture.
- Optional watcher mode accepts one folder only from the CLI. It uses local filesystem events plus a 60-second full reconciliation, inventories image filenames, byte counts, and modification times, and keeps state in memory for this process. It lists new/changed files and images at least 10 MiB; large size is a review signal, never a deletion recommendation.
- Watcher traversal is capped at 250,000 directory entries and the visible queue at 100 candidates. It ignores symlinks, Guardian's `Corbeille`, `.guardian`, `.guardian-quarantine`, and common build/cache folders. If native filesystem events fail, it falls back to periodic checks and labels that mode.
- Current image-extension inventory: PNG, JPEG, WebP, GIF, AVIF, and SVG. Preview is disabled for SVG. Generation-metadata parsing is currently only for PNG text chunks; other types must be labeled not checked, not metadata-free.
- PNG parser reads only the first 1 MiB of the selected PNG, recognizes generation-oriented `tEXt` and uncompressed `iTXt` fields (including Stable Diffusion WebUI `parameters` and ComfyUI `prompt` / `workflow`), and caps each displayed field at 256,000 characters. It does not decode compressed `zTXt`/compressed `iTXt`, parse general EXIF, validate image integrity, or claim every producer is compatible. Truncated or malformed input is reported as partial/incomplete.
- The currently selected file's parsed metadata is held in page memory only. Values are inserted as text, not HTML. Metadata is not placed in browser storage, URLs, logs, or remote requests; changing selection clears the cached result.
- Exact duplicate candidates are grouped by file size, hashed with SHA-256 only when no larger than 64 MiB, and then compared byte-for-byte in bounded chunks before being labeled exact. Read failures and files over the cap are not marked as duplicates.
- Visual candidates are a separate, local perceptual-hash pass over PNG, JPEG, WebP, and AVIF thumbnails. Animated GIF and SVG files are skipped. The engine groups nearby low-frequency image patterns (up to five differing hash bits), caps candidate comparisons at 50,000, yields during work, and supports cooperative cancellation. These groups are heuristic suggestions, not proof of equivalent content, generation provenance, or safe deletion. Nothing is selected automatically.
- Inventory traversal is capped at 250,000 entries; at most 10,000 largest supported images are retained for review. The app reports when these limits, unreadable entries, or the 64 MiB hash cap make inventory/exact-duplicate coverage partial. Visual-hint coverage is reported separately.
- Inventory progress is yielded to the browser every 250 entries. SHA-256 duplicate checks and visual candidate checks use same-origin module workers when available and fall back to the main thread. Only byte-confirmed groups are labeled exact; perceptual groups are always labeled as candidates. Cancellation is cooperative and cannot interrupt one in-flight browser file read, image decode, or Web Crypto digest.
- Folder scans, image bytes, duplicate comparisons, and file operations remain in the local Chromium renderer, including the Windows desktop app. In watcher mode the browser/CLI local service reads metadata from only the CLI-selected folder and sends a bounded relative-path/status snapshot to the same-origin page; image bytes, hashes, and prompts are not returned by the watcher. Neither desktop protocol nor HTTP server accepts caller-supplied filesystem paths or exposes a mutation endpoint. The selected source contains a marked `Corbeille/.guardian-quarantine/manifest.json` and opaque archive data files; paths, reasons, byte counts, hashes, and lifecycle state are sensitive local data.
- Demo records and preview images are generated synthetic samples. Their metadata is also synthetic and must never be confused with a scan of a real image.

## Safety and privacy requirements

- Bind only to IPv4 loopback. Keep the fixed asset allowlist, exact Host validation, GET-only server, cross-origin/cross-site rejection, restrictive CSP, `nosniff`, no-referrer, and same-origin resource policy.
- No caller-supplied filesystem path may be opened by an HTTP request. The watch root is supplied once through the CLI; the only new route is fixed `GET /api/watch/status`, which accepts no query string and performs no file operation. Do not add an upload endpoint or remote request for folder contents.
- The watcher performs only bounded directory enumeration and file metadata reads. It never opens image bytes, selects a candidate, moves, renames, archives, or deletes a file. Do not request write permission during browser scan. The archive button asks for source-folder write permission and creates or opens only the marked `Corbeille` child.
- Never choose a file automatically. Archive is limited to 20 explicitly selected files per operation and requires a complete scan plus an inline exact path/count/byte review before the user activates the archive action. Partial inventory or exact-duplicate scans cannot archive. Visual-hint coverage gaps are reported separately; every chosen file remains a human decision.
- Archive copy is chunked at 1 MiB and verified by byte comparison plus incremental SHA-256. The source entry is removed only after the archived file and durable `verified` journal state have been committed. Permission, write, quota, collision, cancellation, and verification failures leave the source intact; an interrupted owned partial archive can be explicitly resumed after the user reviews the same file again.
- Keep the managed `/Corbeille` subtree and `/.guardian-quarantine` protected from image traversal and selection. Refuse unsafe relative paths and an archive journal that is malformed or exceeds bounds. Never take over a non-empty unmarked folder named `Corbeille`; never overwrite a detected existing archive payload or restore target.
- Restore is explicit, checks the source-relative target before writing, and retains the verified quarantine copy. The user must confirm they selected the original source folder. If a target exists at the check, stop and preserve the archive. A failed restore can leave a partial target which should be inspected before retrying.
- Permanent deletion is a separate irreversible action. The page lists every eligible Corbeille path and stored size inline; a separate acknowledgement checkbox enables **Delete permanently**. Guardian verifies each stored hash before deletion and journals the purge state for interrupted recovery. No typed phrase or dialog is required.
- Report only verified bytes removed from the selected source or from Guardian's Corbeille. Do not claim or measure operating-system free space. Corbeille is inside the source folder, so archiving alone does not reduce total device storage; permanent deletion removes the verified Guardian copies.
- Browser filesystem APIs do not provide a portable atomic no-replace reservation against another application changing the folder between Guardian's preflight check and write. Use this local beta only while other programs are not changing either selected folder; this residual concurrency limitation prevents a claim of OS-level transactional safety.
- Clear transient selection, metadata, and review-plan state on folder switch/rescan or tab close. The local archive journal and bytes are the only persisted operation state; no browser database or remote service is used.
- Never equate large size, visual similarity, or a metadata marker with a reason to remove a file.
- Keep the scope and completeness of scans visible: file-count cap, hash-size cap, partial cancellation, unsupported metadata, and read errors must not be described as full verification.

## Acceptance criteria

- `guardian studio` serves the app only at a loopback URL. Optional `--watch <folder>` monitors one CLI-selected folder; fixed `GET /api/watch/status` accepts no path or query and no write endpoint exists.
- Demo works without a selected folder and clearly marks every demo record/metadata value as synthetic. Watch mode can be off, active, polling, partial, empty, or truncated; the queue is informational and never selects an archive candidate.
- Folder selection remains read-only until separately authorized; the browser never transmits selected file paths, bytes, hashes, or prompts.
- PNG parser tests cover Stable Diffusion WebUI parameters, ComfyUI prompt/workflow, `iTXt`, compressed metadata, malformed/truncated input, bounded values, and unsupported input.
- Exact-duplicate tests cover equal bytes, same-size different bytes, forced hash collision, file read error, oversize skip, and cancellation. Only byte-confirmed groups become selectable.
- Search, filters, sorting, 40-row pagination, preview, details, keyboard focus, review-plan export for selected files, and clear empty/error/partial states work.
- The List / Contact sheet toggle preserves the active search, view and folder filters, sort, page, selected-file inspector, and manually selected review candidates. The contact sheet shows real local previews, full path, name, size, and distinct exact/visual/large signals; similar groups are visually compared together. Similarity remains a hint, large size is informational, and no view or group automatically checks a file.
- PNG prompt/workflow fields require explicit disclosure and are inserted using safe text rendering. The UI clearly labels PNG-only support and the 1 MiB/256,000-character bounds.
- Archive never removes the source before the verified copy and journal commit; failures/cancellation preserve the source and resumable state.
- Restore refuses an existing target and retains its verified Corbeille copy. Permanent deletion requires reviewing the inline path/size list, checking its acknowledgement, and a verified archive hash.
- Managed Corbeille and protected archive data are never scanned; selected archive targets are not intentionally overwritten. Filesystem concurrency limitations are communicated to the user.
- Byte counters never claim OS free-space changes. The UI explains that archived files remain on the same device until permanently deleted.
- Server security tests reject unexpected methods, paths, Host, Origin, cross-site requests, and watch-status query parameters. Watcher tests use disposable folders and verify large/new candidate reporting, protected-directory exclusion, entry caps, and unchanged source bytes.
- CLI smoke check starts `guardian studio --watch <temporary-folder>`, reads `/api/watch/status`, and shuts the process down cleanly.

## Known limitations and next architecture boundary

- The watcher currently monitors one folder supplied at launch. New/changed status exists only for the lifetime of the process; a restart establishes a new baseline. The CLI path is less discoverable than an in-app folder picker and should be tested with pilot users. Category demand is {{UNVALIDATED}}.
- The watcher performs bounded metadata enumeration; it does not verify image content, detect visual similarity, or identify exact duplicates. Use Studio's separate browser scan for byte-confirmed duplicates.
- Native event support varies by filesystem and operating system. Guardian reconciles every 60 seconds, but unusual remote/network filesystem behavior and very large folder performance need wider pilot measurement.
- The compatibility picker and unsupported browsers remain read-only. The optional archive feature depends on the File System Access API. See [MDN directory input](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/webkitdirectory), [`showDirectoryPicker()`](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker), and [`getFileHandle()`](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemDirectoryHandle/getFileHandle).
- Folder traversal is capped at 250,000 entries and the app retains at most 10,000 largest image handles for inspection; larger archives produce partial duplicate coverage. Duplicate hashing is capped at 64 MiB. Archive copy, verification, and archive/purge hashing stream in 1 MiB chunks; cancellation is cooperative and honored at safe chunk/item boundaries.
- Metadata is parsed when a PNG is selected, not indexed across every file. Search does not yet index prompts, workflow graphs, model names, seeds, or parameters across the collection.
- The Windows desktop wrapper is unsigned and not yet release-ready. The file operations still use Chromium browser APIs; they do not provide atomic filesystem transactions, symlink-level guarantees, or protection from another process changing the selected folders concurrently. The desktop watcher is not implemented. Real-file use should follow disposable-folder validation and maintain an independent backup. Signed release packaging and OS-level recovery testing remain open.
- Semantic/AI image matching, crops and composition changes, broad metadata formats (JPEG/WebP/EXIF), automated cleanup, persistent catalogs, and cloud features remain out of scope. Visual candidate matching is only the bounded perceptual-hash hint described above.
